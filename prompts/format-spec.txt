Write findings in this EXACT record format and nothing else outside it. One record per finding:
@@FINDING
sev: important   (use 'important' for a bug introduced by this PR; 'nit' for minor/non-blocking)
loc: path/to/file.ext:123   (a file:line that appears in pr.diff)
conf: high   (high | med | low)
title: one short line
body: one to three sentences on a SINGLE line — the reason grounded in the diff, plus a concrete suggested fix.
Repeat @@FINDING blocks for each finding. If there are NO findings, write no @@FINDING blocks at all.
Then ALWAYS end the file with exactly:
@@PRDESC
summary: ONE short line (max ~30 words) — the riskiest part of the diff and what you verified there. Do NOT recap what the PR does; the author already knows. ALWAYS include this line, especially when there are no findings.
rating: good | could-be-improved | poor
reason: one short line, max ~20 words, explaining the rating (omit this line when rating is good)

Rate the PR description (from pr-meta.json) against what the diff actually does. 'poor' = the PR description is missing/empty, extremely outdated, or contradicts what the diff actually does. 'could-be-improved' = notable gaps or small inaccuracies but acceptable to merge as-is. 'good' = everything else. Do NOT write a replacement description or propose new description text — rating + reason only.
